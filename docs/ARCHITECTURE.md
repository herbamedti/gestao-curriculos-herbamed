# Arquitetura

Monólito modular Next.js App Router. `src/app` contém rotas, `src/modules` regras de domínio e ações, `src/ui` componentes e tokens, `src/lib` infraestrutura. SSR mantém páginas de vagas indexáveis e sessões no servidor. Server Actions fazem validação Zod; RPCs PostgreSQL aplicam autorização e transações. RLS permanece ativa como defesa adicional para leitura e Storage. A chave elevada aparece somente no servidor, no gateway de arquivo, no worker e na troca de senha já confirmada por segundo fator; nunca no navegador. Autenticação no Supabase usa cookies e `getUser()` para validar a sessão.

Fluxo: navegador → Next.js → Supabase Auth/Data API → PostgreSQL/RLS. O currículo é composto de `candidates` e `profile_entries`; a candidatura valida esses dados em RPC. O PDF é gerado no servidor após autorização por RLS e enviado diretamente ao navegador, sem Storage. O fluxo anterior de upload/worker/ClamAV permanece desativado. E-mails de autenticação local usam Mailpit; a outbox transacional aguarda um worker de comunicação na configuração de produção.

Módulos: auth, acesso, candidatos, currículo, vagas, candidaturas, entrevistas, avaliações, mensagens, privacidade, relatórios, auditoria e configurações. A tela de Conta usa código enviado por SMTP do servidor e desafio TOTP do Supabase; a tabela privada de desafios só recebe escrita por RPC restrita à chave secret e não libera acesso via RLS. A senha é atualizada pelo serviço de Auth após a verificação e a chave elevada permanece somente no servidor. O deploy hospedado usa o build Next.js nativo da Vercel, sem conexão direta ao PostgreSQL nem worker persistente. A imagem Docker standalone continua disponível localmente e em outras plataformas.
