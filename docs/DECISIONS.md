# Decisões arquiteturais — 23/09/2026

1. **Monólito modular Next.js App Router + TypeScript estrito.** SSR e metadados para vagas, Server Actions para formulários, Route Handlers para arquivos. React e Next MIT. Domínios separados em `src/modules`; nenhuma infraestrutura de microserviços.
2. **Supabase oficial (Postgres, Auth, CLI).** Migrations são a fonte da verdade; RLS nega acesso por padrão. Identidade do usuário em operações normais. A chave secret fica só no servidor para emitir código de Conta e executar alteração de senha após verificação; RPCs transacionais protegem candidaturas, movimentações e administração sensível. Storage permanece desativado no fluxo atual.
3. **RBAC configurável com escopo de vaga.** Perfis, permissões e atribuições em tabelas. Acesso interno exige conta previamente autorizada, provedor Azure e MFA quando exigido pelo perfil. Login Microsoft sozinho não concede acesso. Seed local habilita explicitamente contas fictícias por senha; nunca executar em cloud.
4. **Vercel nativa para demonstração; Docker local preservado.** O deploy Vercel usa a integração Next.js e funções sob demanda, sem `Dockerfile.vercel` na raiz, conexão PostgreSQL direta ou worker persistente. O arquivo histórico está em `docs/legacy/`, fora da detecção automática de contêiner da Vercel. O Docker Compose mantém o Supabase e a aplicação independentes no computador. O worker antigo só entra em um perfil Docker opcional e não é necessário para currículo estruturado. O plano Hobby não permite uso corporativo; usar Pro/trial elegível.
5. **Material 3 com componentes React próprios e HTML semântico.** Material Web oficial está em maintenance mode. Evitamos dependência estrutural de web components; tokens M3, botões filled/tonal/outlined, navigation drawer, chips, states e escala tipográfica. Inter local e Material Symbols local. Logos fornecidos pela Herbamed.
6. **Currículo estruturado.** Os dados primordiais ficam em `candidates` e `profile_entries`. A RPC valida nome, e-mail, telefone, cidade, atuação, resumo, habilidades e experiência ou formação antes de aceitar a candidatura. Candidato e RH exportam PDF gerado sob demanda, autorizado por RLS. O fluxo anterior de upload em quarentena e ClamAV permanece no código e nas migrations, mas está desativado no modo padrão; nenhum novo arquivo de currículo é enviado ao Storage.
7. **Privacidade por finalidade.** Ciência do aviso não é consentimento universal. Banco de talentos opt-in separado. Retenção e base legal precisam de validação do controlador; nenhuma duração jurídica arbitrária é ativada. IA desligada e desacoplada; não classifica contratação.
8. **Sem dados fictícios como fallback de produção.** Seeds locais identificados na interface. Falha de backend mostra erro, nunca indicadores inventados.

## Plano de entrega

Fundação → identidade/RLS → candidato/documentos → vagas/candidaturas → RH/pipeline → comunicação/privacidade/administração → testes integrados e preparação de produção. Recursos externos só são considerados validados após execução real. A matriz em `docs/STATUS.md` distingue implementado, testado e dependências externas.
